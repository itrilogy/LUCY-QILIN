# 产品查询与 ZIP 安装验证

日期：2026-11-17。对象：本机商店 `http://127.0.0.1:8787`、DSH `@deepseek-ai/dsh` 0.2.2-rc.3。

## 1. 商店 MCP 的查询能力

`search` 支持这些过滤：

| 参数 | 能力 |
|---|---|
| `query` | 名称、摘要、id；3 字以上走 FTS5，短词回退 LIKE |
| `kind` | `skill`、`mcp`、`mcp+skill`、`knowledge`、`plugin`；`runtime` 需显式传 |
| `client` | 适用 AI 工具，例如 `deepseek-harness` |
| `platform` | 适用平台，例如 `darwin-arm64` |
| `sort` | `updated`（默认）、`title`、`id` |
| `limit` / `offset` | 分页 |

行为：

- 不传 `kind`：返回除 `runtime` 外的全部已发布产品（runtime 默认不上货架）。
- 显式 `kind=runtime`：可以查到 runtime。
- 只返回每个包当前可见的最新版本；历史版本用 `list_versions`。
- `kind=mcp` 不包含 `mcp+skill`，两者要分开查。
- **没有知识包的 taxonomy/domain 分面过滤**：`knowledge.taxonomy` 只存在清单里，`search` 只按 kind + 文本过滤。若要做“按企业类目/领域筛选”，需要在 `catalog_index` 增加可过滤列并加参数。

实测（当前商店只有两个插件）：

```json
// kind=plugin
{"items": ["lab.plugin-smoke@1.1.0", "labtwo.plugin-smoke-b@1.0.0"], "total": 2}
// kind=skill / knowledge / mcp / runtime
{"items": [], "total": 0}
// 不传 kind
{"items": ["lab.plugin-smoke@1.1.0", "labtwo.plugin-smoke-b@1.0.0"], "total": 2}
```

## 2. ZIP 下载与安装

| kind | 制品 | 安装方式 | 现状 |
|---|---|---|---|
| `skill` | zip | `download` → `unpack` 到 `${SKILLS_ROOT}/<id>/<version>` → `verify` 入口 | 通过（端到端用例） |
| `knowledge` | zip | `download` → `unpack` 到 `${KNOWLEDGE_ROOT}/<id>/<version>` → `verify` 入口 | 通过（端到端用例） |
| `plugin` | zip | `download` → `plugin_stage` 解压到 `${PLUGIN_STAGING}/<id>/<version>` → `plugin_confirm` → `verify` | 通过（实测 1.1.0） |
| `mcp` | 通常无文件 | `mcp_add` + `verify`（连接并列出工具） | 代码路径已有；远程 MCP 不需要 zip |
| `runtime` | 平台资产，不是 zip | `download` + `place_bin` | 代码路径已有 |

实测 `lab.plugin-smoke@1.1.0`：

- `/v1/install-plan` 返回 `download → plugin_stage → plugin_confirm → verify`；
- 制品下载 **1328 字节**，`zipfile` 可读，sha256 与计划一致；
- 包内文件：`client.js`、`cordis.patch.yml`、`index.js`、`manifest.json`、`package.json`；
- `store install` 实际下载并暂存到 `var/plugin-staging-110/lab.plugin-smoke/1.1.0`，未执行插件代码。

## 3. ZIP 能不能直接被 DSH 安装？

**不能。**

DSH 的 `plugin_manager install_bundle` 接受的是：

- 一个**本地包目录**（绝对路径）；
- 或 npm/git/tarball 形式的包 spec（走 pnpm）；
- 插件索引 format 1 的来源也只有 npm 或 git（见 `dsh-plugin-market-index/src/types.ts`）。

它不接受“任意 zip 解压后直接安装”这种操作。商店的 `plugin_stage` 就是替用户做这一步：

```text
plugin.zip → 解压到 staging 目录 → plugin_manager install_bundle target=<staging目录>
```

所以：

- **zip 可以被商店正确下载、校验、解压；**
- **DSH 不能直接吃 zip；必须先解压成目录**；
- 商店的参考安装器只做到 staging，实际安装由用户在 DSH Plugins 里确认，或让 agent 调 `plugin_manager`。

如果希望 DSH 直接安装，需要把发布形态改成：

- npm 包（私有 registry 或本地 tarball spec），或
- Git 包（commit + path），或
- 自定义一个“下载 zip + 解压 + 调 install_bundle”的 DSH Host 插件（多一段代码，不推荐）。

## 4. 结论

- 商店 MCP 已支持按产品种类、文本、工具、平台、排序、分页查询；**不支持知识包 taxonomy/domain 分面过滤**。
- 技能、知识包、插件的 zip 都能正确下载、校验、解压；技能/知识包可直接落到目录，插件落到 staging。
- DSH 不能直接安装 zip；安装的是 staging 后的**目录**。这是 DSH 的包管理器契约，不是商店的缺陷。
- 若要让 DSH“一键装 zip”，只能改发布形态（npm/git）或写一个解压安装的 Host 插件；前者也与插件索引源的要求一致。
