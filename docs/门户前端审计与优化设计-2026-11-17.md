# 门户前端审计与优化设计

日期：2026-11-17。范围：`store/portal/index.html`（单文件门户，含 CSS 与 JS），以及它调用的 `/v1/*`、`/mcp` 接口在页面上的呈现。目标：找出品类、可用性、可访问性、响应式、性能与可维护性问题，给出可执行的优化顺序。

## 0. 结论

1. **插件品类在货架上缺失的问题已修**：`kind=plugin` 的筛选 chip 已补，货架说明与详情调用说明也已补；详情页原本已有插件分组。
2. **移动端此前没有断点**：固定 240px 侧栏 + 多列 grid/表格在窄屏会挤压。本次补了 900px / 600px 两档断点。
3. **最大的剩余缺口不是样式，而是“插件还不能从门户表单上架”**：`f-kind` 没有插件选项，插件表单字段、审核清单 UI 都还没有；目前只能通过 MCP/CLI 提交，审核清单只能走 HTTP/MCP。
4. **架构上仍是 2,086 行单文件、全局状态、内联 CSS/JS**。短期可维护，长期会拖慢迭代；建议按“先修可用性，再拆文件”的顺序做，不引入前端框架。

## 3. 分区域审计

### 3.1 信息架构与导航

- 左侧 8 个入口：货架、运行时、我的提交、审核、审计、用户、用户管理、连接。角色显隐只做了审计（admin）与用户管理 gate；**“审核”入口对所有登录用户可见**，作者点进去只会看到 403/空队列，建议按角色隐藏或显示“需要审核权限”。
- 货架分类是静态 chip；现在补了插件，但仍是手写清单。建议从 `KIND_LABEL` 生成，避免下次加品类再漏。
- 运行时是独立视图，但 `shelf` 的 `data-kind` 与 `state.shelfKind` 两套状态；打开详情再返回只恢复 `shelf`，不恢复分类/搜索。

### 3.2 货架

- 卡片信息完整：类型、版本、标题、摘要、id、平台/客户端/作者、按钮。缺“更新时间/下载量”等排序依据；当前没有排序控件。
- 搜索只有 `query` 一个字段，匹配名称/摘要/id；后端已支持 FTS，但页面没有提示“3 字以上走全文，短词走子串”。
- 空态是一行字，没有“清空筛选”或“去上架”。
- `loadCatalog` 每次清空 grid，快速切换会闪烁；无骨架。
- `data.total` 已用于计数；但后端默认不分页，货架没有“加载更多”。插件/技能多了以后需要。

### 3.3 详情与安装说明

- 版本表四列，移动端靠横向滚动；建议窄屏改成两行卡片。
- 详情分组：身份/说明/适用/调用/依赖/密钥，知识包和插件各加一组；结构清楚。
- 安装计划是 `<pre>` 原样 JSON，技术用户可读，普通用户不友好；建议“步骤卡片 + 原始 JSON 折叠”。
- 插件详情的 `plugin_stage`/`plugin_confirm` 没有解释“不会执行代码”，只在 `invokeText` 里补了一句；建议在安装说明上方加提示。

### 3.4 上架 / 修订表单

- `f-kind` 只有 5 类，缺 plugin；`syncKind` 也没有插件分支。
- 技能/MCP/知识包/运行时的字段已经按类型显隐；插件需要新增一组：tier、form、entry、client、patch、files、dsh、capabilities、external。
- 表单提交前的 `validate` 错误只显示规则列表，没有按字段定位；插件规则（`PLUGIN_*`）会堆在一起。
- 目录选择 `webkitdirectory` 与文件列表已有；插件 zip/目录需要确认 `package.json` 在根。

### 3.5 审核

- 左队列/右详情结构可用；差异视图是文本 diff，长文件会很长，建议默认折叠。
- **插件审核清单没有 UI**：后端要求 8 项逐项 true，页面无法完成，只能走 MCP/HTTP。这是当前最影响“验收”的前端缺口。
- 审核页没有显示“提交人/提交时间/channel”；审计页有，但审核页应补。

### 3.6 审计

- 过滤（action/package_id）+ 50 条 + 加载更多已实现；`actor_name` 已显示。
- 无“清空筛选”；过滤后空结果只有“共 0 条”。
- 无导出；审计记录只读，导出 CSV 可作为运维增强。

### 3.7 登录 / 账号 / 连接

- 登录对话框有 `aria-labelledby`；注册表单 labels 完整；口令规则实时提示。
- 顶栏 KEY 输入框 CSS 还在（`#key`），但页面没有对应元素，属于死样式；建议删除。
- 连接页有 MCP 配置与 KEY；KEY 只显示一次，复制后没有“已复制/请保存”的持久提示。
- `QILIN_STORE_KEY` 的环境变量说明与页面 KEY 的关系没有在图上一句话讲清；建议加“这是同一把 KEY 的两种用法”。

### 3.8 可访问性与响应式

- 已有：`lang`、`aria-label`、`aria-pressed`、`aria-current`、`aria-required`、`dialog aria-labelledby`、`:focus-visible`、`textContent`。
- 缺：skip link、`main` id、表格 caption、chips 键盘方向键、对话框关闭后的焦点返回、错误 `aria-live`（`state` 无 live region）、移动端导航可滚动提示。
- 本次已加两个断点；但仍需真机/浏览器验证 360/390/768/1024/1280 五档。

### 3.9 性能与安全

- 无 `innerHTML`/`eval`，渲染走 `textContent`，XSS 面小；保持这条纪律。
- 单文件约 100KB，首屏可接受；无第三方字体/脚本，离线友好。
- `fetch` 无超时/取消；错误只显示 message，`rule` 丢失。
- 无 CSP；拆分资源后可加。
- 页面通过 HTTP 提供，KEY 在页面只显示一次；不要把它写进 URL/localStorage。

## 4. 优化设计

### 4.1 原则

1. **不引入前端框架**：商店是本地单进程、stdlib 交付；保持零构建、可直接打开的静态资源。
2. **先修可用性，再拆文件**：P0/P1 的交互修复收益高于目录重构。
3. **渐进增强**：无 JS 时至少能读规范/静态说明；当前是 JS 渲染，保持现状但补错误态。
4. **一条纪律**：所有外部字符串只走 `textContent`；禁止 `innerHTML`，除非是静态模板常量并有测试。

### 4.2 阶段 0（本次已完成）

- 插件 chip、货架说明、插件调用说明。
- 900/600 断点、表格横向滚动、单列详情/表单。
- 搜索 Enter、计数用 `data.total`。
- 测试补插件 chip 与断点断言；`node --check` 通过。

### 4.3 阶段 1（进行中）

已完成：

1. 插件上架表单：`f-kind` 加 plugin；插件分组（tier/form/entry/client/patch/dsh/files/capabilities/external）；插件目录选择；`manifestFromForm` 写 `plugin` 块；`fillForm` 回填；根上 `package.json` 校验。
2. 插件审核清单：审核详情读 `get_review` 的 `plugin_review`；8 项 checkbox + “记录审核”；调用 `/plugin-review`；未记录时发布按钮禁用。

待做：

3. 统一空态/错误态：状态区支持“重试/清空筛选/去上架”按钮；错误显示 `rule`。
4. URL 状态：`#shelf?kind=plugin&q=...`、`#detail/<id>`；返回按钮恢复来源。
5. 角色显隐：审核入口仅 admin；作者不显示用户管理（已 gate，但入口仍在）。
6. 浏览器 E2E：至少覆盖插件表单、审核清单、移动端 390px。

### 4.4 阶段 2（结构性，2–3 天）

1. 拆文件：`portal/index.html`、`portal/styles.css`、`portal/app.js`；`http_api` 静态路由与 `package-data` 同步；移除内联 CSP 障碍。
2. API 模块：`api(path, {timeout, signal})`，GET 失败重试一次；统一错误对象 `{rule, message, status}`。
3. 渲染模块：`renderShelf`、`renderDetail`、`renderReview`、`renderAudit`；DOM 节点查询集中，避免全局 id 散落。
4. 骨架屏 + 请求序号/AbortController，解决快速切换竞态。
5. 表格窄屏卡片化：版本表、审核表、审计表用 `<dl>` 或隐藏次要列。

### 4.5 阶段 3（可选）

- CSP（拆分后 `script-src 'self'`；样式 `style-src 'self'`）。
- i18n key 化；先中文，保留 `locale/zh.json`。
- Playwright 三条 E2E；无浏览器环境跳过。
- 审计导出 CSV；货架排序/加载更多。

## 5. 验收标准

- 桌面 1280：货架六类 chip 可切换，插件卡片与详情正常。
- 移动 390：侧栏变横向导航，货架单列，表格可横向滚动，表单字段不溢出。
- 插件：门户可提交 Tier A 插件（选插件目录、填 tier/form/entry/patch/dsh/files/caps/external）；审核页可记录 8 项清单；未记录时发布按钮禁用，接口仍会返回 `PLUGIN_REVIEW_REQUIRED`。
- 搜索：Enter 触发；短词/3 字以上都能返回结果；计数等于 `total`。
- 可访问性：Tab 能到所有控件；对话框打开/关闭焦点可回；状态区有 `role="status"`。
- 回归：`pytest` 全绿、`node --check` 通过、wheel 包含新增静态文件。
