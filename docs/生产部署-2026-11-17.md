# 生产部署与运行手册

日期：2026-11-17。适用版本：本仓库 `main`。目标：单机、单进程、SQLite + 本地制品目录的商店部署。不是多副本/HA 方案。

## 1. 架构与边界

```text
浏览器 / AI 工具
       │ HTTPS
       ▼
Caddy / nginx（TLS、限流、访问日志）
       │ 127.0.0.1:8787
       ▼
Python 进程（门户 + /v1/* + /mcp）
       ├── SQLite（WAL）  /var/lib/qilin/qilin.db
       └── 制品目录       /var/lib/qilin/blobs
```

- 商店**不执行**安装、不运行插件/技能；只做上架、审核、搜索、安装计划与制品托管。
- 单进程写入 SQLite；不要起多个 `store serve` 指向同一个库。需要多副本时先换数据库与对象存储，不在本手册范围。
- 反代到 `127.0.0.1:8787`，商店不直接暴露公网。

## 2. 目录与账号

```text
/opt/qilin                 代码 + venv
/etc/qilin/qilin.env       环境变量（0600，qilin 可读）
/var/lib/qilin/qilin.db    数据库
/var/lib/qilin/blobs/      制品
/var/log/qilin/            systemd/launchd 日志
/var/backups/qilin/        备份
```

```sh
sudo useradd --system --home /opt/qilin --shell /usr/sbin/nologin qilin
sudo mkdir -p /opt/qilin /etc/qilin /var/lib/qilin /var/log/qilin /var/backups/qilin
sudo chown -R qilin:qilin /opt/qilin /var/lib/qilin /var/log/qilin /var/backups/qilin
sudo chmod 700 /etc/qilin
```

`/etc/qilin/qilin.env` 只放这些，不要把密钥写进仓库：

```sh
QILIN_PUBLIC_BASE=https://qilin.example.com
QILIN_ACCESS_LOG=1
# 接枢纽时才需要：
# QILIN_HUB_ORIGIN=https://hub.example.com
# QILIN_HUB_APP_ID=...
# QILIN_HUB_SECRET=...
# QILIN_HUB_AUTHORIZE=https://hub.example.com/authorize?...
```

## 3. 安装

```sh
cd /opt/qilin
python3 -m venv .venv
.venv/bin/python -m pip install -e .
# 接枢纽 JWT 时：
# .venv/bin/python -m pip install -e '.[hub]'
```

默认只用标准库。`hub` extra 才需要 `cryptography`。

## 4. 启动

手动验证：

```sh
cd /opt/qilin
PYTHONPATH=. .venv/bin/python -m store.cli serve \
  --host 127.0.0.1 --port 8787 \
  --db /var/lib/qilin/qilin.db --blobs /var/lib/qilin/blobs
```

`--public-base` 建议用环境变量 `QILIN_PUBLIC_BASE` 固定为 HTTPS 地址；不要让商店按 `Host` 头猜，否则安装计划/MCP 配置可能下发 http 地址。

### systemd

```sh
sudo cp deploy/qilin.service /etc/systemd/system/qilin.service
sudo systemctl daemon-reload
sudo systemctl enable --now qilin
sudo systemctl status qilin
journalctl -u qilin -f
```

### launchd（macOS）

```sh
sudo cp deploy/com.lucy.qilin.plist /Library/LaunchDaemons/
sudo chown root:wheel /Library/LaunchDaemons/com.lucy.qilin.plist
sudo launchctl load -w /Library/LaunchDaemons/com.lucy.qilin.plist
```

### 反向代理

Caddy（`deploy/Caddyfile.example`）或 nginx（`deploy/nginx.conf.example`）。要点：

- TLS 终止在反代；商店只听 `127.0.0.1`。
- 传 `X-Forwarded-Proto: https`；`QILIN_PUBLIC_BASE` 设成同一个 https 地址。
- 关闭响应缓冲（MCP 流式）；`client_max_body_size` 至少 64m（32MiB 制品 base64 后约 43MB）。
- 只放行 443；8787 不对公网开放。

## 5. 健康检查与日志

- `GET /api/health`：200 表示数据库可读、制品目录可写；503 表示 degraded。返回 `status`、`database`、`blobs`、`identity`，不返回路径。
- `GET /v1/identity`：身份模式（unset/hub）与是否可跳转登录。
- 访问日志：`QILIN_ACCESS_LOG=1` 时写 stderr（systemd journal / launchd 日志）；默认关闭。
- 审计：`/v1/audit` 与 `/v1/audit.csv`（admin），包含提交、发布、退回、下架、KEY 重新生成、插件审核等。

建议探针：

```sh
curl -fsS https://qilin.example.com/api/health | grep -q '"status": "ok"'
```

## 6. 备份与恢复

每日备份（`deploy/backup-daily.sh`）：

```cron
15 3 * * * QILIN_ROOT=/opt/qilin QILIN_BACKUP_DIR=/var/backups/qilin /opt/qilin/deploy/backup-daily.sh >> /var/log/qilin/backup.log 2>&1
```

脚本调用 `store backup`，生成 `qilin.db`、`blobs/`、带 sha256 的 `backup.json`，并按 `QILIN_BACKUP_KEEP`（默认 14 天）清理旧目录。

恢复演练（每季度至少一次）：

```sh
sudo systemctl stop qilin
cd /opt/qilin
PYTHONPATH=. .venv/bin/python -m store.cli restore /var/backups/qilin/2026-11-17 \
  --db /var/lib/qilin/qilin.db --blobs /var/lib/qilin/blobs --force
sudo systemctl start qilin
curl -fsS http://127.0.0.1:8787/api/health
```

`restore` 先核对每个文件 sha256，再写目标；默认拒绝覆盖，`--force` 才覆盖。恢复会带回备份时的账号 KEY 哈希，**备份之后重新生成的 KEY 会失效**。恢复前先停服务。

## 7. 升级与回滚

```sh
sudo systemctl stop qilin
sudo -u qilin /opt/qilin/deploy/backup-daily.sh
sudo -u qilin git -C /opt/qilin fetch --all
sudo -u qilin git -C /opt/qilin checkout <tag-or-commit>
sudo -u qilin /opt/qilin/.venv/bin/python -m pip install -e /opt/qilin
sudo systemctl start qilin
curl -fsS http://127.0.0.1:8787/api/health
```

回滚：停服务 → 切回上一个 commit → `pip install -e` → 启动；数据库迁移是启动时幂等的，旧代码读新库前先看 release notes。需要回到旧数据时按上一节 restore。

## 8. 安全清单

- [ ] 商店只监听 `127.0.0.1`，公网只开 443。
- [ ] 反代 TLS 有效；`QILIN_PUBLIC_BASE` 为 https；Cookie 自动带 `Secure`。
- [ ] `QILIN_HUB_SECRET` 只放 `/etc/qilin/qilin.env`（0600），不进仓库、不进命令历史。
- [ ] **数据库包含 KEY 明文**（内网取舍）：DB 权限 0600、备份加密或放在受控介质，不要把 `qilin.db` 当普通文件传阅。
- [ ] 登录限流：默认每 IP 5 分钟 20 次；注册每小时 10 次；多进程/反代后另配 fail2ban。
- [ ] 管理员账号至少两个；插件审核禁止自审（`SELF_REVIEW`）。
- [ ] 定期备份并做过 restore 演练；备份目录与数据盘分开。
- [ ] 审计定期导出/归档；注意审计 CSV 已做公式注入转义。
- [ ] 插件只从 `plugin_stage` 暂存目录安装；商店不自动执行/安装。
- [ ] 反向代理访问日志保留；应用审计与访问日志分开。
- [ ] 磁盘告警：`blobs/` 会随制品增长；`store backup` 也占空间。

## 9. 已知限制

- 单进程 SQLite，不支持多副本同时写；需要 HA 时先改存储层。
- 限流是进程内滑动窗口；多进程/多实例要由网关或 fail2ban 兜底。
- 插件/技能安装由用户在 DSH/本机确认；商店没有远程卸载能力。
- 没有内置指标/Prometheus 端点；目前靠 `/api/health`、journald 与审计。
- 没有自动数据库压缩/审计归档任务；按部署规模自行加 cron。
