## 4. 运维交接（必须知道的六件事）

1. **空库先建管理员**：`store init-admin --username admin`（容器里 `docker compose exec qilin store init-admin ...`）。空库 HTTP 注册一律 403，这是刻意的。
2. **注册策略**：`QILIN_REGISTRATION=open|closed`（默认 open）。公网部署建议 `closed`，由管理员在「用户管理」开号（口令随机、只显示一次）。自助注册只产生作者。
3. **外部地址抓取**：默认 `QILIN_FETCH_POLICY=public`，只访问公网。内网资源必须加 `QILIN_FETCH_ALLOW_HOSTS`，不要改成 `any`。
4. **单进程、单副本**：`serve` 会在 `<db>.lock` 上取 flock，第二个实例会被拒绝；`restore` 在服务运行时也会拒绝。数据目录必须是本地块存储（不要 NFS/SMB）。
5. **备份**：宿主 cron/systemd timer 跑 `docker compose --profile ops run --rm backup` 或 `store backup`；恢复要先停服。备份里有 KEY 明文（内网取舍），介质要加密。
6. **访问日志**：应用日志已对 `?ticket=` 脱敏；反向代理的 access log 仍会记完整 URL，需在网关侧处理或不记 `/v1/uploads`。

## 5. 回滚

- 代码：`git checkout <上一个可用提交>`，重装/重建镜像；数据库结构迁移目前只有 `user_version=1`，前向兼容。
- 数据：停服后 `store restore <备份目录> --db ... --blobs ... --force`；恢复会把 KEY 回到备份时的状态。
- 容器：固定镜像 tag/digest，回滚就是改 `.env` 里的 `QILIN_IMAGE` 再 `up -d`。

## 6. 已知限制

- 单机单进程，不支持多副本；规模上限约 50 req/s、5,000 个包、50GB 制品。
- 健康检查的 `readyz` 只是"库可读、目录可写"，不覆盖外部依赖。
- 没有内置指标端点；观测靠 `/api/livez`、`/api/readyz`、审计表与容器日志。
- 插件/技能安装由用户在 DSH/本机确认，商店不执行、不远程卸载。
- DNS 在"检查"与"连接"之间会重新解析，SSRF 守卫存在理论上的重绑定窗口。
