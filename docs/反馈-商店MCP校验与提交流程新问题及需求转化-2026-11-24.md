# 反馈与需求转化：Qilin Store MCP 校验链路、依赖探测与提交流程新发现问题

- 日期：2026-11-24
- 反馈来源：Antigravity 客户端在完成 `luxi.paper-arts@4.4.0` 与 `luxi.gov-unified-writer@3.3.0` 全链路提交（`validate` → `begin_submit` → `PUT` → `finish_submit` → `withdraw`）过程中实测暴露的新问题
- 关联记录：[反馈：Antigravity 客户端接入与制品拉取问题](反馈-Antigravity客户端MCP接入与制品拉取问题-2026-11-24.md)

---

## 一、新发现的 5 个问题（均附实测证据）

### 问题 1：`validate` 与 `finish_submit` 校验口径割裂（事前通过、事后拒收）

- **实测证据**：
  - 提交 `luxi.gov-unified-writer@3.3.0` 前调用 `qilin-publish:validate`，返回 `{"ok": true, "rules": [], "findings": []}`。
  - 执行 `begin_submit` + `PUT` 上传后，调用 `finish_submit(submission_id="5e43ce5bc8a842de")` 被直接拒收：
    - `status: "rejected"`
    - `FRONTMATTER_CONFLICT: summary 必须是 frontmatter description 的缩短`
- **根因**：
  1. `validate` 仅接收 `manifest` JSON 对象，不校验压缩包内 `SKILL.md` 的 frontmatter 与 `manifest.json` 跨文件一致性；
  2. `get_spec("skill")` 仅描述“name、description、能解析的 version 不得和清单说成另一件事”，未明文写出 **`manifest.summary` 必须是 `SKILL.md` frontmatter `description` 的前缀缩短** 这一严格规则。

### 问题 2：`DEP_EXTERNAL_UNREACHABLE` 在内网/离线商店环境下阻断合法基础依赖声明

- **实测证据**：
  - 商店已上架的 `luxi.paper-arts@4.3.0` 与 `luxi.gov-unified-writer@3.2.0` 原包均合法声明了 `python3 >=3.9` 与 `https://www.python.org/downloads/`。
  - 本轮升级 `4.4.0`（`28e945a87d912e3c`）与 `3.3.0`（`8245a9384400e03d`）在 `finish_submit` 阶段连续 3 次被拦在 `status: "uploading"`，报错 `DEP_EXTERNAL_UNREACHABLE: https://www.python.org/downloads/ 地址当时打不开`。
  - 最终只能从 `manifest.json` 中删除 `depends.external` 声明（改为 `[]`），重新打包为 `03fd87d12df39cc3` 与 `bd2e5014f78f0b93` 才得以转为 `pending`。
- **影响**：内网部署商店服务器无法连通外网时，强探测外部 URL 会倒逼作者**清空 `depends.external` 元数据**，导致安装器丧失前置运行环境自动探测（`detect`）与引导能力。

### 问题 3：`uploading` 状态提交无法通过 `withdraw` 撤回或清理

- **实测证据**：
  - 尝试用 `withdraw` 清理停留在 `uploading` 状态的 `28e945a87d912e3c` 与 `8245a9384400e03d` 时，返回错误：
    `{"rule": "VERSION_UNAVAILABLE", "message": "只能撤回待审核的提交"}`
- **影响**：一旦因网络或校验中断产生 `uploading` 半成品提交，提交者无法自行取消、清理占位记录或回收服务端临时上传文件，造成 `list_my_submissions` 列表污染。

### 问题 4：大/多文件 Skill 上传路径存在工具规范矛盾

- **实测证据**：
  - `submit_package` 要求将全部文件以 base64 键值对形式内联到单次 MCP 工具调用 JSON 参数中，面对 20~30 个文件的 Skill 包极易造成调用上下文膨胀。
  - 改用 `begin_submit` 时，工具描述要求“由安装器对 `put_url` 做 PUT，不要自己编上传命令”，但 MCP 工具集本身未提供配套的文件路径直传或上传代理工具，Agent 仍需自行执行 `curl -X PUT` 完成上传。

### 问题 5：`VERSION_UNAVAILABLE` 错误码语义过载

- **实测证据**：同一错误码 `VERSION_UNAVAILABLE` 当前至少承载了 4 种完全不同的异常：
  1. 服务端制品路径不可读（`制品文件不可读`）
  2. 品类无制品（`这个产品没有可下载的制品`）
  3. 撤回非 `pending` 状态的提交（`只能撤回待审核的提交`）
  4. 目标版本确实不存在/已下架

## 二、转化后的产品与工程需求清单

| 需求编号 | 对应问题 | 需求标题 | 具体改进要求与验收标准 | 优先级 |
| :--- | :--- | :--- | :--- | :---: |
| **REQ-01** | 问题 1 | **`validate` 支持跨文件前置校验与规范文档补全** | 1. `validate` 增加可选参数（如 `skill_md` 或 `frontmatter`），支持提交前即校验 `FRONTMATTER_CONFLICT`；<br>2. 在 `get_spec("skill")` 中明文补充 `summary` 必须为 `description` 前缀缩短的规则；<br>3. `validate` 返回字段中明确标注哪些规则仅在 `finish_submit` 阶段执行。 | **P0** |
| **REQ-02** | 问题 2 | **外网依赖可达性检测分级与离线策略支持** | 1. 服务端增加配置开关/内网模式：允许对已知基础运行时（`python3`、`node`、`git` 等）免除 `resources[].url` 外网强探测，或将 `resources` 改为可选字段（仅保留 `name`、`version_range`、`detect`、`install_guide`）；<br>2. 将 `DEP_EXTERNAL_UNREACHABLE` 降级为可配置的 `warning`（由审核员人工复核），而非阻断 `pending` 流转。 | **P0** |
| **REQ-03** | 问题 3 | **支持撤回/取消 `uploading` 状态提交** | 扩展 `withdraw`（或新增 `cancel_submit`）支持 `uploading` / `rejected` 态草稿的主动取消，并清理服务端临时上传切片与对象文件；同时增加服务端超期未完成 `uploading` 记录的 TTL 自动回收机制。 | **P1** |
| **REQ-04** | 问题 4 | **提供 MCP 本地路径打包提交能力（或统一 PUT 桥接工具）** | 在 `qilin-publish` 中新增安全受控的本地包提交能力，或提供标准 `upload_artifact(put_url, zip_path)` MCP 工具/CLI 子命令，消除 `submit_package`（base64 膨胀）与 `begin_submit`（禁止自编 PUT 命令）之间的工具断层。 | **P1** |
| **REQ-05** | 问题 5 | **细分错误码体系，消除 `VERSION_UNAVAILABLE` 过载** | 拆分错误码：`ARTIFACT_MISSING`（磁盘文件缺失，HTTP 503）、`KIND_NO_ARTIFACT`（品类无制品，HTTP 400/422）、`SUBMISSION_STATE_INVALID`（提交状态不允许当前操作，HTTP 409）、`VERSION_NOT_FOUND`（版本不存在，HTTP 404）。 | **P1** |
