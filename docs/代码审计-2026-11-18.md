## 2. 审计发现

### 已修（本轮）

1. **审核不能下架**：`unpublish` 仍要求 `admin`，与“审核可下架”冲突。已改为 `REVIEW_ROLES`，并加用例。
2. **命名空间不能转给审核**：`transfer_namespace` 的目标角色仍只判断 `publisher/admin`，排除了 `reviewer`。已改用 `PUBLISHER_ROLES`。
3. **`store/roles.py` 死代码**：角色常量已定义但未被使用，各处仍是字面量。已把 auth/submissions/catalog 的角色判断统一到常量，避免再次漂移。
4. **账号测试与 KEY 策略冲突**：测试仍断言 `/v1/me` 不含 KEY；已改为断言 `store_key` 与当前 KEY 一致。

## 3. 角色矩阵（现状）

| 角色 | 提交 | 审核/发布/下架 | 审计/贡献 | 用户管理/角色/转移 |
|---|---|---|---|---|
| `member` | 否 | 否 | 否 | 否 |
| `publisher` | 是 | 否 | 否 | 否 |
| `reviewer` | 是 | 是 | 是 | 否 |
| `admin` | 是 | 是 | 是 | 是 |

- 本地账号默认 `publisher`；
- 自审全 kind 禁止；
- 管理员可以审核；审核不能管理用户；
- `reviewer` 账号已从 admin 降为 reviewer，`kwangwah` 保留 admin。

## 4. KEY 与激活（现状）

- 新账号/重新生成后：`key_plain` 持久化，`/v1/me` 返回 `store_key`，连接页直接显示发布配置；
- 旧账号无明文：第一次点一次「重新生成 KEY」，之后持久化；
- 页面只有一个 KEY 面板、一个重新生成按钮，没有粘贴已有 KEY 入口；
- 发布配置直接带 KEY 明文，配置名称固定 `qilin-store` / `qilin-publish`。

## 5. 贡献数据链路

- 提交时服务端覆盖 `author` 快照：publisher_id、username、real_name、nickname、department、job_title；
- 公开 `describe` 只输出 `display_name`；
- 审核页、`get_review`、贡献页、`list_contributions` 可见完整快照；
- 统计按已发布版本，产品数/版本数/类型/最近发布。

## 9. 2026-11-18 复审追加

当前工作树又包含一轮修订（HTTP 三段上传/撤回/下架、`validating` 状态、已发布制品归档、`PRAGMA user_version`、ETag、`--trust-proxy`、字段级错误定位、窄屏卡片、审核 diff 折叠）。复审结果：

- 文档中的 P2 声称已基本核实：`portal_e2e.py` 复用固定作者、`roles.py` 只保留常量、审核 diff 折叠、字段级 `aria-invalid`、`--trust-proxy`、会话清理均有对应代码。
- **发现并修复**：登录限流此前只按 `(IP, 用户名)` 计数，换用户名可绕过每 IP 次数；现在同时按 IP 和 `(IP, 用户名)` 两个键计数，成功登录同时清空两者，并加测试。
- **仍待观察**：`submit` 在锁外打包后二次 `_prepare`，但没有重新跑完整校验；版本/归属变化会拒绝，依赖清单变化只会用到旧快照，属于可接受的竞态窗口。
- **仍待观察**：已发布制品同时保留 `submissions/*.zip` 与 `releases/<id>/<version>.zip`，磁盘会多一份；如果确认审核历史不需要保留提交包，可加归档后清理策略。
- **仍待观察**：E2E 固定账号在 `var/accounts/e2e-author.json`，若账号被停用会回退新建；属于测试夹具，不影响生产。
