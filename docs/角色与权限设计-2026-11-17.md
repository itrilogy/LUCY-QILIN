# 角色、权限与激活设计

日期：2026-11-17。范围：门户登录、商店 MCP 工具可见性、发布 KEY 激活、贡献数据。

## 1. 为什么发布按钮会置灰

不是角色不够，是**页面拿不到 KEY 明文**：

- 服务端只存 KEY 的 scrypt 哈希；
- 登录只建立会话，不返回 KEY 明文；
- 明文只在创建账号或重新生成 KEY 的那一次出现；
- 发布配置要直接写入 KEY 明文，所以作者/审核登录后默认没有明文，发布标签置灰。

管理员和作者在这里没有区别；这是存储模型，不是权限。

### 激活方式（二选一）

1. **已有 KEY**：在「连接」页粘贴保存过的 KEY，点「用已有 KEY 激活」；页面用 `/v1/me` 校验它属于当前账号，然后写入发布配置，不轮换 KEY。
2. **没有 KEY**：点「重新生成 KEY」；旧 KEY 立即失效，新 KEY 显示一次并写入发布配置。

只有一个 KEY 面板、一个「重新生成 KEY」按钮；不再有第二个重复入口。

## 2. 角色模型

| 角色 | 标签 | 默认 | 能力 |
|---|---|---|---|
| `admin` | 管理员 | 第一位账号 | 作者 + 审核 + 用户管理、角色分配、停用、重置口令、命名空间转移 |
| `reviewer` | 审核 | 管理员提升 | 作者 + 审核、发布、退回、下架、审计、贡献 |
| `publisher` | 作者 | 之后创建的账号 | 提交/修订/撤回自己的产品、读、安装 |
| `member` | 只读 | 枢纽 viewer/外部 | 读、安装；不能提交/审核 |

- 本地创建账号**默认 publisher**，非管理员同样具备作者能力。
- 审核不是管理员：不能管理用户、改角色、停用、重置口令、转移命名空间。
- 管理员可以审核，也可以把作者提升为审核/管理员。
- 最后一位管理员不能被降级或停用。
- 分离职责：任何人都不能批准自己提交的产品（`SELF_REVIEW`，所有 kind）。
- 管理员自提交产品时，需要另一个审核/管理员批准。

## 3. MCP 工具可见性

| 角色 | 可见 |
|---|---|
| 匿名 / `member` | `PUBLIC`：get_spec、search、list_versions、resolve、describe、install_plan、artifact |
| `publisher` | PUBLIC + 提交/修订/我的提交/撤回 |
| `reviewer` | PUBLIC + 提交 + 审核/发布/退回/下架/审计/贡献 |
| `admin` | 全部 + `transfer_namespace` |

不是根据“页面按钮”判断，而是 KEY 的角色决定工具集合；页面置灰只影响复制配置，不影响 KEY 已能调用的工具。

## 4. 发布信息与贡献数据

提交时服务端按账号写入 `author` 快照：

- `publisher_id`、`username`、`real_name`、`nickname`、`department`、`job_title`

清单里自填的账号字段会被覆盖，防冒用。

可见范围：

- 公开货架 / `describe`：只返回 `display_name`；
- 审核页 / `get_review`：完整快照；
- 贡献页 / `list_contributions`：完整快照 + 产品/版本统计。

贡献统计按**已发布版本**：

- 排行：产品数、版本数、类型分布、最近发布时间；
- 明细：产品/版本/类型/标题/发布时间；
- HTTP `GET /v1/contributions`，MCP `list_contributions`，均只给审核/管理员。

## 5. 表单设计调整

- 上架表单顶部增加分组导航：身份、阐述、适用、插件、调用、依赖、密钥、制品。
- 分组标题自动编号；`#sheet` 限宽 980px，长表单不再铺满整屏。
- 「已有 KEY」输入与「重新生成 KEY」合并在一个面板；发布标签、KEY 明文、激活状态在同一处。
- 提交者信息由账号显示，作者显示名自动预填；服务端仍以账号快照为准。

## 6. 迁移与运维

- 旧 `admin` 账号保持管理员，不自动降级；管理员可在用户管理里把某个账号改为审核。
- `reviewer` 是新角色值；已有数据库无需迁移列，只是枚举多一个值。
- 重新生成 KEY 会清掉旧会话；E2E 已改为使用“粘贴已有 KEY”，不再轮换真实账号。
