## 0. 结论

**一句话**：这是一个工程质量明显高于平均水平的单机内网商店——路径守卫、SQL 参数化、公开视图白名单、一次性上传票据、WAL 快照读都做得对——但它现在**不能直接对公网开放**，而且**修订链路有一个确证的数据丢失缺陷**。

三条必须先处理的事：

1. **修订 runtime 包会清空该提交的平台资产记录**（`store/submissions.py:410` 插入、`:417` 同一事务内又全删）。修之前上线，被退回的 runtime 包一旦"修订 → 发布"，该版本所有平台制品都下载不到。现有测试只覆盖 skill 包，所以一直是绿的。（已复现，**2026-11-20 已修复**，见 §7）
2. **开放注册 + 第一个注册者自动成为管理员**（旧 `store/auth.py:260`）+ **上传完成时服务端会主动请求清单里的任意 https 地址**（旧 `store/validator/net.py`）。两条都已在 2026-11-20 修掉：管理员只能 `store init-admin`、注册可关；抓地址默认只允许公网，带重定向校验与 20 个地址 / 45 秒预算。
3. **只能单副本**。写锁、限流桶、KEY 缓存、启动时全量重建索引都是进程内状态。2026-11-20 已加 flock 单实例断言：第二个 `serve` 指向同一个库会直接拒绝启动。

就绪度判断：

| 场景 | 结论 |
|---|---|
| 内网、单机、可信用户 | 可用（P1-1/P1-2/P1-4/P1-7/P1-9 已修，商品数据已迁移演练） |
| 公网 / 多租户 / 有外部注册者 | 需要 §5 的 P1 全清 + 反代 ACL；注册建议 `closed`，外部地址策略保持 `public` |
| 多副本 / 高可用 | 不支持，需换 PostgreSQL + 对象存储，工作量另计 |

## 2. 现状

### 2.1 运行时结构

```text
浏览器 / AI 工具 / DSH
        │ HTTPS
        ▼
反代（Caddy / nginx）           TLS、限流兜底、访问日志
        │ 127.0.0.1:8787
        ▼
store serve（单进程 · ThreadingHTTPServer · 每请求一线程）
        ├─ /                     门户（CSP: script-src 'self'）
        ├─ /v1/*                 账号·提交·审核·发布·审计·安装计划
        ├─ /mcp                  JSON-RPC（tools/list, tools/call, resources/*）
        ├─ /v1/artifacts/...     制品下载
        └─ /api/health           就绪探针
        │
        ├── SQLite WAL（1 写锁 + 每线程一连接 + BEGIN 读快照）
        └── blobs/{submissions,uploads,releases,assets}
```

### 2.2 值得肯定的设计

- **路径只有一个入口**：`store/safety.py` 的 `safe_join` 在写树、ZIP 解包、runtime 资产、备份恢复四处复用，先形状检查再 `resolve()` 比对基准目录。
- **公开视图是白名单**：`store/views.py` 只吐 `_PUBLIC_MANIFEST_KEYS`，作者信息收成 `display_name`，`publisher_id` 不外泄。
- **票据原子消费**：`UPDATE ... WHERE used_at IS NULL` + `rowcount == 1`，并发重放只有一个成功。
- **读快照**：`_read()` 显式 `BEGIN` + `rollback`，写锁不挡读，`tests/test_concurrency.py` 真的证明了这点。
- **错误面克制**：500 只回 `trace_id`，异常原文进日志；审计 CSV 做了公式注入转义；`_path` 剥掉查询串。
- **前端零 HTML 注入面**：2,191 行里没有一处 `innerHTML`，渲染收敛到 `text()/cell()`；CSP 无内联脚本，与实现一致。
- **测试诚实**：`tests/test_rule_contract.py` 把规格第 12 节与 `errors.SPEC_RULES` 双向对齐。

### 2.3 关键取舍（不是 bug，但要写进部署约束）

| 取舍 | 现状 | 代价 |
|---|---|---|
| KEY 明文入库 | `accounts.key_plain`，`/v1/me` 每次下发（`store/auth.py:174`） | 拿到 DB / 备份 / 会话 = 拿到永久发布凭据 |
| 单进程写锁 | 进程内 `RLock`，KEY 缓存 10s 生效 | 不能多副本，多进程会半坏 |
| 服务端主动探网 | 上传完成时 GET 清单里的 URL | 盲 SSRF，必须有网段与预算限制 |
| 管理员引导 | 空库只能 `store init-admin`；自助注册只产生作者（2026-11-20 起） | 部署时多一步 CLI；换来空库不怕暴露 |
| 制品下载不鉴权 | `/v1/artifacts` 无 token 校验（`store/http_api.py:276`） | 与门户"需登录下载"文案矛盾（见 P1-5） |

## 3. 问题分级

### P0：无

没有一条能直接导致"未授权写入 / 任意文件读写 / RCE"。曾经有两个条件性 P0（抢注管理员、盲 SSRF），2026-11-20 都已修掉：管理员只能 `store init-admin`，抓外部地址默认只允许公网。

### P1（上线前必须处理）

#### P1-1 修订 runtime 包会清空平台资产（已复现，已修复）

```python
# store/submissions.py:409-418
self._keep_assets(submission_id, root, stored)          # 410：插入新 submission_assets 行
...
self._db.execute("DELETE FROM submission_assets WHERE submission_id = ?", ...)  # 417：全删
```

`_keep_assets` 只对 `kind == "runtime"` 写 `submission_assets`（`store/submissions.py:696`），紧接着的 `DELETE` 把刚插入的和旧的资产行一起删掉。文件还留在 `blobs/assets/<sid>/<platform>`，但 DB 行没了 → `approve` 时 `_publish_assets` 查不到 → `release_assets` 为空 → `artifact()` 对 runtime 报 `PLATFORM_MISMATCH`；安装计划仍按清单生成下载 URL，装到一半 404。

修复（已落地）：把 `DELETE FROM submission_assets` 挪到 `_keep_assets` 之前，并把这两步放进带 `rollback` 的 try 里；`tests/test_revise.py` 增加 runtime 修订与"修订失败清空资产"两条用例。回退修复后新用例立刻失败（`[] != ['darwin-arm64']`），可确认用例真的拦得住。

#### P1-2 开放注册 + 首个账号自动管理员（已修）

旧 `store/auth.py:260`：`role = "admin" if 空表 else "publisher"`。`POST /v1/account` 无需邀请、无需审核，只有 10 次/小时/IP 的限流。空库一旦暴露到公网，第一个请求就是管理员。

同类风险面还有两处：
- 注销/停用只删本地会话，**枢纽 JWT 在 `exp` 前仍然有效**（`store/auth.py:72-79` 不查 `accounts.disabled_at`）。
- `--hub-origin` 模式下的角色完全由 JWT 里的 `app_roles` 决定，商店侧没有第二道闸。

修复（已落地）：
- 自助注册**只产生作者**（`_register_account` 的 `role` 由调用方给，默认 `publisher`）；
- 管理员只能由 `store init-admin` 引导，或由现有管理员在「用户管理」里授予/开号（新增 `POST /v1/accounts`，管理员专用，口令随机生成只回一次）；
- 空库时 `/v1/account` 直接 403 `REGISTRATION_CLOSED`（管理员不存在就先引导），不存在"抢先注册"窗口；
- `QILIN_REGISTRATION=open|closed` 控制自助注册，`/v1/identity` 下发 `registration` 与 `has_admin`，门户据此隐藏注册表单；
- 新增规则 `REGISTRATION_CLOSED`（已同步规格第 12 节），注册被拒会进鉴权日志。

**仍未处理**：枢纽 JWT 在 `exp` 前不受 `disable_account` 影响（下面同一节的第二点）；`--hub-origin` 模式下角色完全由 JWT 的 `app_roles` 决定。

#### P1-3 盲 SSRF：上传完成时请求清单里的任意 URL（已修）

`store/submissions.py:227` → `validate_path(..., check_urls=True)` → `store/validator/net.py:9-30`：`urlopen` 直接发，HEAD 失败再 GET，跟随最多 10 次重定向，单次超时 10s；只要求 `https://`，不拦内网、回环、链路本地（`169.254.169.254`）、重定向到 `http://`。

后果不是"读出数据"，而是：① 端口/存活探测 oracle（结果通过 `DEP_EXTERNAL_UNREACHABLE` 回给提交者）；② 对内网服务触发 GET 的副作用；③ `depends.external[*].resources` 数量无上限 → 一个请求可以挂住一个 handler 线程数百秒。

修复（已落地）：`store/validator/net.py` 重写为"守卫 + 预算"：
- `QILIN_FETCH_POLICY=public|allowlist|any`，默认 `public`——解析结果里只要有一个非公网地址就不访问（回环、私网、链路本地、元数据、ULA 等，用 `ipaddress.is_global` 判断）；
- `QILIN_FETCH_ALLOW_HOSTS` 给内网资源开白名单（精确主机或按点边界的域名后缀），而不是把策略改成 `any`；
- 重定向每跳重新过策略，禁止 https→http；被拦下与"打不开"同样返回 `None`，不给提交者当端口探针；
- 单份清单最多 20 个地址、总预算 45 秒，单次探测超时从 10s 降到 5s；
- 残余风险：DNS 在检查与连接之间会重新解析，理论上有重绑定窗口（已写进模块注释与部署文档）。

#### P1-4 登录限流可被合法用户清零（已复现，已修）

`store/http_api.py:332-333`：登录成功即 `reset(ip)` 与 `reset(ip:username)`。攻击者注册一个自有账号，交替"成功登录自己 → 猜受害者一次"，两个桶每次归零，绕过 5 分钟 20 次的限制。同时 `_RateLimiter` 在 key 打满时 `self._events.clear()`（`:49`）会清空**所有人**的窗口——一次随机用户名洪水就能给攻击者解封（已复现：`_RateLimiter(2, 60, max_keys=64)` 在被 70 个 key 打满后重新放行 victim）。

修复（已落地）：登录成功**不再重置任何桶**（窗口按时间自然过期）；键表打满时只清过期键，仍然满就**拒绝新键**（fail closed），不再 `clear()` 整表——旧实现等于一次随机键洪水给所有人解封。`RATE_LIMITED` 已并入鉴权日志（默认级别下可见）。回归用例：`tests/test_rate_limit.py` 的"成功登录不清零"和"表满拒绝新键而不清表"。

#### P1-5 制品可匿名下载，与门户文案矛盾（2026-11-20 决策：保持匿名，已改文案）

`store/http_api.py:276` 直接调 `store.artifact()`，`store/catalog.py:650` 的签名里没有 token —— 匿名可下 `skill/knowledge/plugin`，runtime 带 `?platform=` 也可下。而门户三处写着"均需要登录后，才能在页面进行下载"（`store/portal/index.html:55,98`、`app.js:707`），并且门户**根本没有下载入口**（全文件无 `/v1/artifacts` 调用）。

这是产品决策而不是纯 bug。**2026-11-20 决定保持匿名**，于是把不成立的文案与用例改掉：

- 门户三处：`index.html:55`（"产品下载不需要登录"）、`index.html:98`、`app.js:470/471/707`；
- 规格 `agent-store-design.md:5,1003` 同步（原来"页面下载须先登录"与"制品地址匿名可下载"自相矛盾，现在统一为匿名；「安装说明」仍需登录后才请求安装计划，这一点保留）；
- `tests/test_portal.py:43` 的断言改成新文案。

行为没有变化：`GET /v1/artifacts/...` 依旧不校验凭据，安装器与 AI 工具照旧直接取。

#### P1-6 KEY 明文的全生命周期暴露

链路：DB 明文（`auth.py:270`）→ `/v1/me` 每次下发（`auth.py:174,208`）→ 门户写入 `<pre id="connect-key">`（`app.js:2075`）→ 一键进剪贴板（`app.js:1902`）。**登出只清 `state.issued`，不清理 DOM**（`app.js:194-199`），公用机器上下一位用户 `document.getElementById('connect-key').textContent` 就能拿到。

**2026-11-20 决定继续接受内网取舍**，不改实现。下列降级路径仍然有效，留给将来对公网开放时用：① `QILIN_ALLOW_PLAINTEXT_KEY=0` 时不落明文，改为"点一次、换一次、看一次"；② 登出清 DOM（一行代码）；③ 备份加密（`store/backup.py` 不加密）；④ `/v1/me` 不下发 `store_key`，单独走 `/v1/account/key/reveal` 且限流+审计。至少做 ② 和 ④。

#### P1-7 未知输入参数直接变 500（已复现，已修）

| 输入 | 结果 | 原因 |
|---|---|---|
| `/v1/catalog?offset=99999999999999999999` | 500 `INTERNAL` | `int()` 通过，绑到 SQLite 抛 `OverflowError`；`do_GET` 的 `except` 元组（`http_api.py:284`）不含它 |
| 提交 `files` 里同时有 `a` 与 `a/b` | 500 | `views._write_tree` 抛 `FileExistsError`（`store/views.py:192`），`safe_extract` 对同情形有专门处理，两条入口不一致 |
| `/v1/catalog?limit=abc` | 400，但 message 里带 `ValueError: invalid literal...` | `http_api.py:287` 回显异常类型与原文 |

修复（已落地）：新增 `_int(query, key, default, lo, hi)`，`limit` 夹到 1–500、`offset` 夹到 0–10,000,000，解析失败回 400；`views._write_tree` 对"文件/目录同名"与 `manifest.json` 被占成目录统一抛 `CHECKSUM`（不再让 `FileExistsError` 冒成 500）；400 的 message 换成一句可操作的话（`缺少字段：id` / `请求体不是合法 JSON。` / `请求体或参数不符合规格。`），不再回显异常类名与原文。顺带修了 `catalog.search_page` 回显原始 `limit` 的问题（P3-11）。

#### P1-8 修订表单会静默丢数据（已修）

`store/portal/app.js:831` 只回填 `depends.external[0]`，`app.js:1169-1182` 只提交一条 → 有两条外部命令的包，修订后剩一条。`app.js:846` 用 `id version` 写依赖行，`app.js:1101` 用 `split(/\s+/, 2)` 读回 → 范围 `>=1.5 <2` 回填后只剩 `>=1.5`。没有提示、没有 diff 警告，审核页看到的是"作者自己删的"。

修复（已落地）：把"表单表达不了的部分"从原清单带回来，而不是继续扩大表单。
- 新增 `store/portal/manifest_merge.js`（独立文件、不依赖 DOM）：`parseDepLines` 只在**第一个**空白处切，`>=1.5 <2` 这种范围不再被截断；

#### P1-9 没有单实例保护（已修）

`store/base.py:50` 承认写锁是进程内的；启动时还会 `DELETE FROM catalog_index` 全量重建（`store/catalog.py:293`）、全局把 `validating` 改回 `uploading`（`store/base.py:211`）、跑 `ALTER TABLE` 迁移（`:215`）。两个 `store serve` 指向同一个库会互相踩：迁移可能直接失败、货架短暂为空、停用的 KEY 在另一副本上还能用 10s、正在校验的提交被改回 uploading。

修复（已落地）：`store serve` 启动时在数据库旁对 `<db>.lock` 取 `flock(LOCK_EX|LOCK_NB)`，拿不到就打印"另一个 store serve 正在使用 …"并退出 1；锁随进程退出由内核释放。Windows 没有 `flock` 时退回不加锁。用例在 `tests/test_bootstrap.py::SingleInstanceTests` 里起两个真进程验证。

### P3（择机）

- `semver` 不接受 build 元数据、接受 `1.0.0-01`；表达式不支持 `^ ~ ||`，`">= 1.0.0"`（空格）静默判 False（`semver.py:15,74`）。
- 非法版本统一排序为 `(1,0,0,0,())`，`max()` 的"最高版本"可能不稳定（`semver.py:54`）。
- `Backup`：`restore` 用 `copytree(dirs_exist_ok=True)` 合并，旧制品残留；不做 `PRAGMA integrity_check`（`backup.py:114`）。
- 审计表无 `action/at` 索引、无来源 IP、无 request id（`base.py:381`）。
- `health()` 用 `os.access` 判可写，root/容器里恒真。
- 知识包密钥扫描只认 `sk-*`/`Bearer`/PEM；`secret` 子串匹配文件名会误报。
- 规则 `MCP_URL_UNREACHABLE`/`MCP_LIST_FAILED` 在规格里声明但从未产出（`errors.py` 有、`validator/` 无调用点）。
- 前端：规则码原样显示（`SPEC_VERSION`、`add_platform`）、审计导出是整页跳转、安装计划 URL 不可复制、描述不保留换行、移动端明细表缺标签。

## 4. 功能优化与完善建议

按"用户能感知的价值 / 投入"排序。

### 4.1 账号与凭据（建议 W7 第一批）

1. ~~**注册闸门**~~（2026-11-20 已做）：`QILIN_REGISTRATION=open|closed`（默认 open，公网建议 closed）；首个管理员只能 `store init-admin`；空库 HTTP 注册直接 403；管理员可在「用户管理」直接开号。邀请码表没做——需要时再加。
2. **KEY 单次换取**：`/v1/me` 不再返回 `store_key`；门户改为"点击查看（限流+审计）"或"重新生成后只显示一次"。这是把 P1-6 从"接受风险"变成"可关闭风险"的最小改动。
3. **登出清态**：登出后清空 `#connect-key`、`#connect-tab-body`、重置表单、重置 `state.role`。
4. ~~**统一 401/403 降级**~~（2026-11-22 已做）：新增 `AUTH_REQUIRED`（401）表示没登录/凭据失效，`ROLE_FORBIDDEN`（403）表示角色不够；401 带 `WWW-Authenticate: Bearer`；门户捕获 401 直接重开登录框，403 只在身份确为匿名时兜底。`KEY_INVALID` 仍留 400——它是"不能自设 KEY"的参数错误，不是认证失败。
5. **会话治理**：登录时保留"同账号旧会话"策略可配置；过期会话与 hub 登录按天清理（现在靠请求命中时顺手删）。

### 4.2 上架 / 审核 / 发布闭环

1. **状态机收口**：把 `validating`、`expired` 并进 `states.py`，禁止 `submissions.status` 出现字符串字面量（加一条测试断言）。
2. **发布原子化**：`releases + catalog_index + audit` 放进一个事务；`_audit` 不再自带 `commit()`，由调用方决定边界。崩溃恢复用"启动时对账"（已发布但索引缺失 → 重建该包）。
3. **发布前校验制品**：`approve` 检查 `artifact_path` 存在、sha256 与记录一致，缺了直接 `CHECKSUM` 拒绝。
4. **下架可逆**：`unpublish` 保留记录但允许重新上架（或 `_release_exists` 只拒"从未下架"的版本），避免误下架只能升版本。
5. **审核体验**：审核页已有 diff 折叠与字段级错误，下一步是"清单级变更摘要"（依赖增删、平台变化、外部命令增删）——这是 reviewer 真正需要判断的东西。

### 4.3 运行时与安装器

1. **`detect` 命令必须显式确认**：安装器会执行清单里的 `detect` 与 `mcp.command`（`installer.py:191,411`）。插件有 checklist，非插件包没有任何"外部命令逐条确认"。建议在 `store install` 交互里列全命令并要求 `--yes` 才执行非白名单命令。
2. **资产与范围**：semver 表达式补 `^ ~ ||` 与预发布规则，或用成熟实现；`runtime.assets` 的 `sha256` 在服务端再核一次（现在只在 `_keep_assets` 时算，清单里的值未比对）。
3. **安装计划可复制**：把下载 URL 做成可点/可复制单行，少一次手抄出错。

### 4.4 可观测性（当前最薄的一块）

1. **日志**：`RATE_LIMITED`、`rejected`、登录失败都进日志；给每个请求一个 `request_id` 并回写响应头，与访问日志、500 的 `trace_id` 对齐。
2. **指标**：`/metrics`（Prometheus 文本格式，标准库即可）暴露：请求数/状态码、`/mcp` 工具耗时、活跃线程数（`_Server.active_requests()` 已经有了）、DB 大小、blobs 大小、WAL 大小、限流命中数。单机部署用 Prometheus + node_exporter 足够。
3. **健康分层**：`/api/livez`（进程活着）与 `/api/readyz`（库可写、blobs 可写、迁移完成）。容器 liveness 用前者，readiness 用后者——现在的 `/api/health` 两者混在一起，DB 一忙就会让编排器重启进程。

### 4.5 HTTP 语义与前端体验

- 413（超限）、415（Content-Type）、HEAD、OPTIONS、`Retry-After`、`Range/206`（大制品）、HTTP/1.1 keep-alive（顺带把 `Expect: 100-continue` 处理好）。
- 门户：`<form>` + 回车提交、`hashchange`/`popstate`、畸形 hash 兜底、错误码中文化、`aria-live` 别把 KEY 念出来、主题首帧不闪、描述 `white-space: pre-line`。

### 4.6 运维与部署（详见配套文档）

- 单实例 `flock`。
- 制品写入改 `.part` + `fsync` + `os.replace`，让"备份时抓到的文件"要么完整要么不存在。
- 备份：加密、异地、季度恢复演练；`restore` 前跑 `PRAGMA integrity_check`。

## 5. 测试与工程改进

### 5.1 覆盖缺口（按风险）

1. 限流器容量淘汰与"成功登录重置"的利用链（现在 `tests/test_rate_limit.py:60-84` 反而把重置写成期望行为）。
2. 修订 runtime 包（P1-1 就是漏在这里）、上传票据并发重放、`_write_tree` 路径冲突。
3. HTTP 方法语义：HEAD/OPTIONS/413/415/206、`Accept` 协商。
4. Host 头与 `Origin`/`Referer`：现在只测了"形状非法"的 Host。
5. MCP 会话头、协议版本、批量请求、参数类型错误。
6. SSRF 约束：重定向、内网地址、URL 数量、总预算。
7. HTTP 层并发（`tests/test_concurrency.py` 只测 `Store` 层）。

### 5.2 脆弱测试

- `tests/test_mcp.py:71` 断言 `HTTP/1.0 405`，把"没有 keep-alive"写死；改协议版本会连带改测试。
- `tests/test_deployment.py:200` 的 `assertGreater(_MAX_BODY, ...)` 是恒真式。
- `tests/test_deployment.py:142` 把"无条件信任 `X-Forwarded-Proto`"固定为期望（P2-15）。
- `tests/test_portal.py:275` 成功分支不断言状态码。
- `tests/test_malformed.py:88` 名为"连接存活"，实际两条 TCP，证明不了什么。
- 多个测试 `addCleanup(server.shutdown)` 后再 `addCleanup(server.server_close)`，LIFO 导致先关 socket 再 shutdown，偶发噪声。

### 5.3 CI

现有 CI（4 档 Python + ruff + compileall + pytest + JS 语法 + wheel 冒烟）已经很齐。建议补：

1. `docker build`（不需要推送）——镜像坏了现在 CI 发现不了。
2. `ruff` 全规则（当前只 `E9`/`F`），至少加 `I`（import 排序）、`B`（bugbear）、`UP`。
3. `scripts/portal_e2e.py` 进 CI（需要服务 + 浏览器；可用 `docker compose up` + Playwright 容器）。
4. 覆盖率门槛（`pytest --cov`，先设 70% 防回退，不必追高）。

### 7.1 一次真实踩坑（记录，供运维参考）
